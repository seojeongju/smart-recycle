# 1차 구현

**프로젝트:** smart-recycle (Smart Recycle)  
**기간:** 2026-09-01  
**상태:** MVP 1차 완료, 외부 테스트 가능  
**관련 문서:** [PRD.md](./PRD.md)

이 문서는 PRD가 아니라 **실제로 만들어 배포된 1차 범위**를 기록한다. 이후 작업은 이 문서를 기준으로 2차를 잡으면 된다.

---

## 1. 한 줄 요약

사진을 찍거나 검색하면 분리배출 단계를 알려 주고, 근처 특수 수거함 지도와 일일 인증(포인트·캐릭터)까지 돌아가는 **모바일 웹앱**을 Cloudflare에 올려 둔 상태다.

외부 주소: https://smart-recycle.jayseo36.workers.dev  
코드: https://github.com/seojeongju/smart-recycle

## 2. 1차에서 한 일

| 구분 | 내용 |
|------|------|
| 제품 | 촬영/앨범 인식, 텍스트 검색, 단계 가이드, GPS 지도, 익명 포인트·스트릭·새싹이 |
| UI | 모바일 웹앱(하단 탭). 월렛 앱 템플릿 참고해 라임 그린 + 화이트 + 차콜 |
| 카메라 | 숨은 file input 대신 `getUserMedia`로 앱 안 후면 카메라 촬영 |
| 인프라 | Workers + Static Assets, D1, R2, Workers AI, Cron 스텁 |
| 배포 | GitHub `main` 푸시, Wrangler로 프로덕션 배포 |

PRD의 M0~M5(골격·검색·인식·지도·게이미케이션·다듬기)는 1차에 모두 들어가 있다. 공공데이터 API 실연동, 소셜 로그인, 지자체별 규정 분기는 넣지 않았다.

## 3. 기술 구성

```
브라우저 (PWA 매니페스트)
  Vite + React 19 + React Router 8 + Tailwind CSS 4 + Leaflet
        │
        ▼
Cloudflare Worker  `smart-recycle`
  Hono API  /api/*
  SPA fallback (index.html)
        ├── D1   smart-recycle-db     카탈로그·수거함·유저·인증
        ├── R2   smart-recycle-images 인식·인증 이미지
        ├── AI   Workers AI           DETR 객체 검출
        └── Cron 매일 03:00 KST       공공데이터 동기화 스텁
```

| 항목 | 값 |
|------|-----|
| Worker 이름 | `smart-recycle` |
| 계정 | `jayseo36@gmail.com` |
| D1 ID | `bdaab975-8617-48a6-b208-d02992426162` |
| R2 버킷 | `smart-recycle-images` |
| 바인딩 | `DB`, `IMAGES`, `AI` |
| 로컬 개발 | `npm run dev` → http://localhost:5173 |

Workers Pages가 아니라 **Workers + Static Assets**다. GitHub Builds 자동 배포는 대시보드에서 저장소 연결이 남아 있다. 1차 배포는 `npx wrangler deploy`로 했다.

## 4. 화면

하단 탭 4개. 데스크톱에서는 가로 430px 폰 프레임.

| 경로 | 탭 | 역할 |
|------|-----|------|
| `/` | 홈 | 인사, 촬영 배너, 품목 바로가기 8칸, 오늘의 팁 |
| `/search` | 검색 | 키워드·카테고리 칩, 결과 목록 |
| `/items/:id` | (가이드) | 단계형 배출 가이드, 업사이클 팁, 인증 |
| `/map` | 지도 | GPS, 유형 필터, 마커·거리·길찾기 |
| `/me` | 마이 | 포인트 카드, 새싹이, 7일 루틴, 별명, 활동 내역 |

최초 1회 **Welcome** 온보딩(`localStorage`: `smart-recycle_onboarded_v2`).

### 홈 바로가기

페트, 플라스틱, 캔, 유리, 종이, 비닐, 폐의약품, 의류 → `/search?q=...`

### 촬영

1. **촬영하기** → 권한 요청 후 전체 화면 카메라. 초록 버튼으로 스냅샷.  
2. 권한 거부·미지원 시 안내 문구.  
3. **앨범**은 갤러리만 연다.  
4. 이미지는 클라이언트에서 긴 변 1280px JPEG로 줄인 뒤 `POST /api/recognize`.

카카오톡·인스타 인앱 브라우저에서는 카메라가 막힐 수 있어 Chrome/Safari를 권장한다.

## 5. 기능 상세

### 5.1 인식

- 모델: `@cf/facebook/detr-resnet-50`
- COCO 라벨을 내부 카테고리로 매핑 후 대표 품목 가이드 연결
- 신뢰도 0.55 미만 또는 매핑 실패 → “잘 모르겠어요” + 검색 유도
- 분당 10회 제한, 결과는 `recognition_logs`에 기록
- 이미지는 R2 `uploads/{userId}/...` 에 저장

1차에서는 비전 LLM(Qwen 등) 2차 분류는 넣지 않았다. DETR + 카탈로그 매핑 + 검색 폴백이다.

### 5.2 검색·가이드

- 품목명, 별칭, 카테고리명 LIKE 검색, 최대 8건
- 가이드: 요약, 배출함, 단계, 업사이클 팁(최대 2), 특수 품목은 지도 딥링크
- 인식과 검색이 **같은 `GuideView`** 를 쓴다

### 5.3 지도

- Leaflet + OSM, 기본 좌표 서울시청 (위치 거부 시)
- 반경 3km, Haversine 거리
- 유형: 폐의약품, 소형가전, 의류, 재활용 정거장, 폐건전지
- 데이터는 D1 시드(서울 시청·강남·홍대·신촌 등). 공공데이터포털 실연동은 Cron이 “키 없음”만 기록하는 스텁

### 5.4 게이미케이션

- 회원가입 없음. `eid` 쿠키(HttpOnly, 1년)로 익명 유저
- 당일 첫 인증 +10P / +10 XP, 같은 품목 당일 재인증은 0P
- 스트릭: KST 자정 기준, 하루 빠지면 0
- 레벨: `floor(total_xp / 50) + 1`, 캡 10
- 캐릭터 기본 이름 새싹이, 별명 1~12자

인증: 쿠키 `eid`. `/api/health` 제외하고 없으면 발급.

|--------|------|------|
| GET | `/api/health` | `{ ok, name: "smart-recycle" }` |

## 10. 로컬·배포 명령

```bash
npm install
npm run db:migrate:local
npm run dev

npm run build
npx wrangler d1 migrations apply smart-recycle-db --remote
npx wrangler deploy
```

원격 D1 마이그레이션은 1차에서 이미 적용했다. `wrangler.jsonc`의 `database_id`는 실 ID이며 GitHub에 포함되어 있다.

## 11. 1차에서 확인한 것 / 남은 것

**확인함**

- 검색·가이드·수거함·인증 API (로컬·프로덕션)
- 같은 품목 당일 두 번째 인증 포인트 0
- GitHub 푸시, workers.dev 배포
- 촬영이 앨범만 열리던 문제 → 인앱 카메라로 수정 후 재배포

**아직 안 함 (2차 후보)**

- 공공데이터포털 실연동 (API 키 + Cron 본구현)
- GitHub → Workers Builds 자동 배포 (대시보드 Connect)
- 비전 LLM 2차 분류, 다중 품목 한 장 인식
- 소셜 로그인, 계정 복원
- 지자체별 배출 규정
- 인식 이미지 7일 R2 lifecycle 자동화
- 푸시·배출일 캘린더

**알려진 제약**

- Workers AI는 원격 GPU라 로컬/첫 요청이 느릴 수 있고, 모델이 쓰레기 품목에 약하면 검색 폴백이 주 경로가 된다.
- 인앱 브라우저·카메라 권한 거부 시 촬영 불가.
- 익명 쿠키를 지우면 포인트·캐릭터가 초기화된다.
- 지도 시드는 서울 위주라 다른 지역은 마커가 적을 수 있다.
