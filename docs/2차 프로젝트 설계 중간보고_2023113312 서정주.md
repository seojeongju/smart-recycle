## 1. 보고 목적

1차 기획서는 주제·핵심 기능·8주 일정을 정의했다. 본 문서는 그 기획을 **실제 설계와 구현 상태**로 옮긴 중간 점검이다.

중간보고에서 확인할 것:

1. 1차 기획의 문제 정의와 기능 범위가 유지되는지  
2. 기획 당시 가정한 기술 스택이 왜, 무엇으로 바뀌었는지  
3. 화면·데이터·API·AI 파이프라인이 어떻게 고정됐는지  
4. 일정 대비 진척과 남은 위험

이 문서는 구현 일지가 아니라 **설계 중간본**이다. 코드 세부는 구현 문서를 따른다.

## 2. 1차 기획 요약

1차 기획서(2026-08-31)의 한 줄 주제는 다음과 같다.

> AI 비전 기술과 공공데이터를 활용한 **스마트 분리수거 및 리사이클링 도우미** 웹/앱 서비스 개발

### 2.1 기획이 잡은 문제

분리배출 규정이 재질·지자체마다 달라 시민이 검색·단지 안내문에 의존한다. 폐의약품·의류·소형가전은 일반 수거함이 아닌데도 위치를 모르기 쉽다. 올바르게 버려도 피드백이 없어 습관으로 이어지기 어렵다.

### 2.2 기획 기능 4가지

| 번호 | 기획 기능 | 의도 |
|------|-----------|------|
| F1 | AI 기반 쓰레기 객체 인식 및 가이드 | 촬영/업로드 → 세척·라벨·배출 요령을 카드로 안내 |
| F2 | 위치 기반 특수 수거함 지도 | 공공데이터 API + GPS, 폐의약품·소형가전·의류함 등 |
| F3 | 친환경 리사이클링 팁 | 업사이클 아이디어를 가이드와 함께 제공 |
| F4 | 바이브 코딩 | 프롬프트 기반 개발로 프로토타입 속도를 높임 |

### 2.3 기획 일정 (8주)

| 단계 | 기간 | 기획서 주요 내용 |
|------|------|------------------|
| 1단계 기획·설계 | 1~2주차 | 요구사항, 와이어프레임, 아키텍처 |
| 2단계 프론트·AI | 3~4주차 | React/Next.js UI, AI 비전 API 연동 |
| 3단계 지도·DB | 5~6주차 | 공공데이터 지도, Supabase 연동 |
| 4단계 통합·QA | 7주차 | 예외 처리, UX 최적화, 사용자 테스트 |
| 5단계 발표 준비 | 8주차 | 보고서, 코드 정리, 시연 영상 |

학기 시작을 2026-09-01로 보면, 본 중간보고 시점(2026-10-05)은 **대략 5~6주차**, 기획상 3단계(지도·DB)와 4단계(통합) 사이이다.

## 3. 기획 대비 설계 변경

핵심 사용자 가치(찍고 → 확인하고 → 버리고 → 인증한다)는 유지했다. 바뀐 것은 **구현 수단**이다.

### 3.1 기술 스택 변경

| 구분 | 1차 기획 | 2차 설계(현재) | 변경 이유 |
|------|----------|----------------|-----------|
| 프론트 | React / Next.js | Vite + React 19 + React Router 8 + Tailwind CSS 4 | 카메라·지도 SPA면 충분. SSR 부담을 줄임 |
| 백엔드·호스팅 | (명시 약함) | Cloudflare **Workers + Static Assets** | UI와 `/api/*`를 한 프로젝트·한 배포로 묶음 |
| DB | Supabase | Cloudflare **D1** (SQLite) | 카탈로그·수거함·익명 유저를 엣지에서 조회 |
| 이미지 | (미정) | **R2** | 인식·인증 사진, 송신료 없이 보관 |
| AI | 외부 비전 API | **Workers AI** (DETR → Qwen → Moondream) | 별도 GPU 서버 없이 같은 Worker에서 추론 |
| 지도 | 공공데이터 지도 API | Leaflet + OSM + D1 수거함 | 타일 API 키 없이 MVP 가능. POI는 자체 DB |
| 앱 형태 | 웹/앱 | 모바일 웹 + **PWA** | 스토어 없이 홈 화면 설치 |

Pages가 아니라 Workers + Static Assets를 쓴다. Cloudflare도 신규 풀스택은 Workers 쪽을 권장한다.

### 3.2 기획에 없던 설계 추가

중간 구현에서 기획 4기능만으로는 루프가 끊겼다. 아래를 설계에 넣었다.

- **텍스트 검색 폴백:** 오인식·미인식 시에도 답을 찾게 함  
- **익명 인증·포인트·새싹이:** 하루 한 번 가벼운 루틴  
- **인식 확인 화면:** “이 물건 맞나요?” 후 가이드로 진입  
- **가이드 체크리스트:** 필수 단계를 끝내야 인증  
- **배포 파이프라인:** GitHub Actions → Wrangler 배포

### 3.3 이번 학기 비범위 (기획·PRD 공통)

- 네이티브 앱스토어 배포  
- 소셜 로그인·계정 복원  
- 한 장에서 여러 품목 동시 인식  
- 지자체 조례 완전 자동 동기화  
- 푸시·배출일 캘린더  
- 관리자 CMS, 포인트 현금화

## 4. 시스템 설계

### 4.1 논리 구성

```
[브라우저 PWA]
  Vite + React + TypeScript + Tailwind
  Leaflet 지도
        │  HTTPS, Cookie eid
        ▼
[Cloudflare Worker  smart-recycle]
  Hono  /api/*   (run_worker_first)
  그 외 SPA (index.html)
        ├── D1   smart-recycle-db      카탈로그·수거함·유저·인증
        ├── R2   smart-recycle-images  인식·인증 이미지
        ├── AI   Workers AI            DETR / Qwen / Moondream
        └── Cron 매일 03:00 KST        약국 공공데이터 동기화
```

| 항목 | 값 |
|------|-----|
| Worker | `smart-recycle` |
| D1 | `smart-recycle-db` (`bdaab975-8617-48a6-b208-d02992426162`) |
| R2 | `smart-recycle-images` |
| 바인딩 | `DB`, `IMAGES`, `AI` |
| 시크릿 | `PUBLIC_DATA_API_KEY` (코드에 넣지 않음) |
| 로컬 | `npm run dev` |

### 4.2 핵심 루프

```
촬영/앨범
   → 로딩(사진 정리 · 품목 살펴보기 · 배출 방법)
   → “이 물건 맞나요?” (맞아요 / 아니에요 / 대안)
   → 가이드 체크리스트
   → 오늘 인증(+10P, 새싹이 XP)
   → (특수 품목) 지도 바텀시트 · 길찾기
```

미인식이면 유사 품목·카테고리 칩·최근 검색으로 같은 가이드에 들어간다.

### 4.3 화면 구조

모바일 퍼스트, 하단 탭 4개. 데스크톱은 가로 430px 프레임.

| 경로 | 탭 | 역할 |
|------|-----|------|
| `/` | 홈 | 촬영·앨범, 품목 바로가기, 설치 배너 |
| `/search` | 검색 | 키워드·카테고리 칩 |
| `/items/:id` | (가이드) | 단계 체크, 업사이클 팁, 선택 인증 사진 |
| `/map` | 지도 | GPS, 유형 필터, 바텀시트, 출처 |
| `/me` | 마이 | 포인트 지갑, 새싹이, 7일, 거래 내역 |

최초 1회 한국어 온보딩 3장(`smart-recycle_onboarded_v3`).

### 4.4 데이터 모델

```
waste_categories 1──* waste_items 1──* waste_aliases
waste_items 1──* guide_steps
waste_items 1──* upcycle_tips
users 1──* checkins
users 1──* recognition_logs
collection_bins
search_logs
sync_jobs
recognition_feedback
```

마이그레이션: `0001_init.sql`, `0002_seed.sql`, `0003_phase2.sql`.

시드: 카테고리 12, 품목 18(투명/유색 페트, 배달 용기, 폐의약품 등). 특수 수거함은 시드 + 공공데이터 약국 upsert.

### 4.5 API 계약

인증은 쿠키 `eid`(HttpOnly, 1년). 없으면 서버가 익명 사용자를 만든다.

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/health` | 생존 확인 |
| GET | `/api/categories` | 카테고리 |
| GET | `/api/search?q=` | 품목 검색 |
| GET | `/api/items/:id` | 가이드 |
| POST | `/api/recognize` | 이미지 인식 |
| POST | `/api/recognize/feedback` | 맞아요/아니에요 |
| GET | `/api/bins` | 근처 수거함 (`source` 포함) |
| GET | `/api/bins/:id` | 수거함 상세 |
| GET | `/api/me` | 포인트·레벨·스트릭 |
| PATCH | `/api/me` | 별명 |
| POST | `/api/checkins` | JSON 또는 사진 multipart |
| GET | `/api/checkins` | 인증 내역 |
| POST | `/api/sync` | 공공데이터 수동 동기화 |
| GET | `/api/sync/status` | 동기화 상태 |

에러는 `{ "error": { "code", "message" } }` (한국어 메시지).

## 5. 핵심 기능 설계

### 5.1 AI 인식 (기획 F1)

클라이언트는 긴 변 1280px JPEG로 줄인 뒤 `POST /api/recognize`로 보낸다.

```
1. DETR(@cf/facebook/detr-resnet-50)로 객체 힌트
2. Qwen(@cf/qwen/qwen3.8-27b)이 카탈로그 item_id만 선택
3. 실패 시 Moondream
4. 그래도 실패하면 DETR 카테고리 대표 품목
5. 최종 실패는 검색 폴백
```

신뢰도 0.55 미만이거나 매칭 실패면 `fallback: true`. 모델은 카탈로그 밖 이름을 짓지 못하게 도구 호출·JSON으로 묶는다. 분당 10회, 결과는 `recognition_logs`에 남긴다.

1차 구현은 DETR만 썼고, 2차에서 LLM 2단을 넣었다. 3차에서 확인 화면을 붙여 오인식이 가이드로 바로 넘어가지 않게 했다.

### 5.2 검색·가이드·팁 (기획 F1, F3)

검색은 품목명·별칭·카테고리 LIKE, 최대 8건. 인식과 검색이 **같은 `GuideView`** 를 쓴다.

가이드 필드: 한 줄 요약, `bin_type`, 단계 `{ order, title, body, required }`, 업사이클 팁(최대 2, `caution` 가능). 특수 품목은 `/map?type=...`로 연결한다.

필수 단계를 체크해야 인증 버튼이 켜진다. 인증 사진은 선택이며 R2 `checkins/`에 90일 보관한다.

### 5.3 특수 수거함 지도 (기획 F2)

| 유형 | 표시 | 데이터 |
|------|------|--------|
| medicine | 폐의약품 | 공공데이터 약국 + 시드 |
| electronics | 소형가전 | 시드 |
| clothing | 의류 | 시드 |
| recycle_station | 재활용 정거장 | 시드 |
| battery | 폐건전지 | 시드 |

- Leaflet + OSM, 기본 좌표 서울시청  
- 반경 3km, Haversine  
- 하단 시트에 목록·상세, 카카오맵 길찾기  
- 출처: `약국 수거함 · 공공데이터` / `참고 위치`  
- 배너: “○○ 기준 · 안내는 일반 기준이에요”

공공데이터는 국립중앙의료원 전국 약국 정보(`B552657` `getParmacyListInfoInqire`). Cron이 시·도를 돌아가며 최대 5페이지(약 1,000곳)를 upsert한다. 키가 없으면 시드만 유지하고 `sync_jobs`에 기록한다.

의류·소형가전은 전국 표준 API가 약국만큼 일정하지 않아 **이번 학기는 시드**로 둔다.

### 5.4 습관화 (기획 보완)

회원가입 없음. 당일 첫 인증 +10P / +10 XP. 같은 품목 당일 재인증은 0P. 스트릭은 KST 자정, 하루 빠지면 0. 레벨은 `floor(total_xp / 50) + 1`, 상한 10. 포인트는 현금이 아니다.

### 5.5 PWA

매니페스트 `standalone`, 서비스 워커, 192·512 PNG(`any` + `maskable`), iOS 180 아이콘. 홈에 설치 배너. **오프라인 캐시·푸시는 아직 없다.**

| 구분 | 내용 |

| 2차 구현 | 인식 LLM, 미인식 UX, 약국 Cron, Actions, R2 lifecycle |
| 3차 구현 | 확인 화면, 가이드 체크, 지도 시트, 온보딩·PWA·마이 지갑 |

## 8. 중간 점검

### 8.1 기획 목표 대비

| 기획 목표 | 중간 판단 |
|-----------|-----------|
| 30초 안에 버리는 법 | 촬영→확인→가이드까지 연결됨. AI 지연은 로딩 카피로 완화 |

### 8.2 확인한 것

- 검색·가이드·인증·수거함 API (로컬·프로덕션)  
- 같은 품목 당일 두 번째 인증 0P  
- 약국 수동 동기화 후 D1 적재

## 9. 결론

1차 기획의 네 축(인식 가이드, 특수 수거함 지도, 리사이클 팁, 바이브 코딩)은 설계에 그대로 남아 있다. 달라진 점은 Next.js·Supabase 가정이 **Cloudflare Workers + D1 + R2 + Workers AI**로 바뀐 것이다. 한 배포 단위에서 카메라, 추론, 지도, 인증이 돌아간다.

중간 시점 기준으로 핵심 루프는 프로덕션에 올라가 있다. 후반은 기능 확장보다 **시연 안정화와 사용자 테스트, 발표 산출물**에 비중을 둔다.
